# Release 2026.10.29.4 — HTTP workflow creation and node inspector

Frontend-only release. The workflow designer now uses the existing HTTP-compatible UUID helper (`crypto.getRandomValues`) instead of secure-context-only `crypto.randomUUID`. New definition, cloned definition, new node and new connection creation work on plain HTTP origins.

Added an adjacent node inspector inspired by the AvaLink editor. New nodes open it immediately; existing nodes expose a settings button and selection highlight. Admin can edit the stage title, notification channel/recipient/message, condition and threshold, delay duration, and each outgoing route with a dropdown. Nodes can be duplicated or deleted. Assignment and approval retain the existing task assignee/approver rules, explicitly described in the inspector. Published versions remain read-only and can be cloned into a draft.

The canvas fits newly added nodes, handles edge selection/deletion and highlights selected nodes. Unsaved work blocks creating another new definition. Version list buttons no longer shrink into overlapping text.

Validation: production TypeScript/Vite build; seven frontend checks including UUID generation in a VM with `getRandomValues` and no `randomUUID`; browser test on a non-localhost HTTP origin: new definition, add notification node, customize title/channel/recipient/text/route, save and reopen persisted properties. Production data was not used for the browser tests.

API remains 2026.10.29.3. No database/schema changes. Roll back only the frontend using:

`bash /opt/taskmanagment/releases/2026.10.29.4/rollback.sh --apply`

Use `--check` for a non-mutating prerequisite check. Previous image and Compose file remain on the server. No API restart or database restore is required.

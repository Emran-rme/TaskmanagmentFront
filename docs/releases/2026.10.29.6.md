# Release 2026.10.29.6 — recoverable workflow cascade deletion

Admin can select a saved draft or published workflow version and choose **Delete workflow and dependents**. The preview lists tasks, project choices, affected definitions and counts of reports/history/notices/attachments. Tasks directly running that definition and their descendants are always included. Only projects explicitly linked to the definition or its task instances are candidates: a company default never selects every company project.

Shared projects start unchecked. Selecting a project includes all its live tasks and all workflow definitions directly assigned to it, which are shown in the refreshed preview. Unselected projects and unrelated definitions survive. Deletion runs in one serializable transaction; a snapshot fingerprint rejects stale previews after dependencies or versions change. Admin/company scope checks apply on the server. Creating tasks or saving/publishing definitions also protects against concurrent project/workflow deletion.

Deletion is recoverable, not permanent. Rows share a deletion batch ID, actor and timestamp. Existing independently deleted rows are untouched. Bookmarks remain stored, while deleted tasks are excluded from workflow queries/timers. **Trash → Workflows → Restore** restores only the same batch, including selected projects, affected definitions, tasks and dependents. Individual children cannot be restored before their workflow batch. Restored definitions remain inactive; existing instance state is preserved, and due timers may continue after their tasks become visible again. Files remain in storage.

Four additive columns on FlowDefinitions: IsDeleted, DeletedAt, DeletedBy, DeleteBatchId. No task or project columns are changed. API restart resets in-memory sessions, so users must sign in again.

Validation: disposable LocalTest HTTP regression covering direct descendants, explicit shared-project selection, stale preview rejection, Admin denials, unrelated entity preservation, full restoration and preservation of earlier independent deletions. Browser verified project selection recalculates from 2 to 10 tasks, delete success, workflow trash and batch restore. Existing permission/authentication/email suites and seven frontend checks pass. Existing workflow SQLite schema upgrades without losing definitions; the previous API binary can read the upgraded database with its workflow engine disabled. No production records were deleted by tests.
